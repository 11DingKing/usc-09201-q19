# 森林碳益共享账领域约定

项目面向集体林权改革与林下产业协作场景。村集体把持续管护形成的碳收益
分给林农与运营方，但**基线/方法版本、监测周期与证据、贡献比例由不同
机构分别维护**。本系统的核心约束是：

> 余额只能由只追加（append-only）的事件重放得到；监测更正、份额变化、
> 边界变化、重复核证、负调整与争议冻结，都只能通过"新事件"改变余额，
> 已经支付的款项永远可解释、可追溯。

业务记录需要区分来源、发生时间与当前有效版本。涉及个人、机构或敏感地点
的信息只向职责范围内的角色开放，所有对外结果都必须能追溯到采用的数据
版本。

## 事件链与版本锁定

* 所有业务事实是链式哈希保护的事件（`service/store.py`）：每个事件记录
  前一事件哈希，任何篡改都会被 `verify_chain()` 发现；事件以 JSONL 持久化。
* 写命令支持幂等键：同一键重复提交返回原事件，参数不一致则报错。
* 每个结算期每次"确认"生成一个不可变分配版本（`allocation.confirmed`），
  快照中锁定：方法版本与参数哈希、每地块监测证据版本与核证回执、碳价、
  边界、生效份额规则、可分配量与各方金额，并计算 `allocation_hash`。
* 确认后若证据被更正，旧版本状态转为 `stale` 但金额与哈希原样保留；
  再次确认生成新版本，历史版本清单可供审计。

## 流水类型与余额口径

金额单位为分。每方每期净应付 `outstanding`：

| 流水 | 影响 | 说明 |
| --- | --- | --- |
| confirmation | +应分 | 首次确认 |
| true_up | 可正可负 | 新版本相对旧版本的追补（监测/份额/边界变化） |
| withheld | 0（锁定） | 暂缓，不改变净应付，仅占用可付额度 |
| payment | − | 实际支付 |
| released | − | 解除暂缓并支付 |
| reclaimed | −（临时） | STALE 期间收回暂缓款 |
| claimback | + | 负调整后参与方退回多付款，冲平负数责任 |
| frozen / unfrozen | 0 | 争议冻结/解除，记录冻结额度 |

* 更正后若旧版已部分支付：新版本确认时按新应分重算，净应付为负即形成
  **追补收回责任**（`claimback_due_cents`），由参与方退回。
* STALE 期间禁止一切对外支付；允许先收回暂缓款（retained）。该收回款在
  下一版本确认时按"分配差额 + 收回款"一次结清：更正幅度小于收回款的
  部分以正向 true_up 补付参与方，大于的部分转为追补收回责任。

## 监测证据与核证回执

* 证据按期、按地块维护版本，新版本以 `corrects_version` 指向旧版本；
  旧证据永不删除。
* 核证回执由核证机构登记，**同一回执只能被一份证据占用**，重复提交拒绝。
* 边界内地块在确认时必须都有最新证据；地块份额合计必须恰为 10000 bps。

## 争议冻结

争议分方向：`outward` 冻结对外支付（剩余应付），`inward` 冻结追补收回
（参与方退回）。冻结只通过 `dispute.opened/resolved` 事件改变可操作额度，
不改变净应付；冻结超额、对冻结金额支付或收回都会被拒绝。

## 角色与敏感信息

`service/access.py` 中的角色：办公室 admin、审计 auditor、监测 monitor、
运营方 operator、林农 forest_farmer、公众 public。

* 参与方只能下载本方对账单；监测机构可见证据链但不可见分成财务；
* 证件号仅 admin 可见，auditor 看到打码值；监测原始位置 URI 对参与方脱敏；
* 公众只能凭 `allocation_hash` 做存证核验，得不到任何敏感字段；
* 各角色下载到的分配哈希完全一致，作为各方对账的共同锚点。

## 模块

* `service/models.py`：枚举、事件、读模型。
* `service/store.py`：链式事件存储、幂等、JSONL、完整性校验。
* `service/ledger.py`：重放、版本锁定、确认/暂缓/支付/追补/冻结规则。
* `service/access.py` / `service/app.py`：角色权限、脱敏与应用编排。
* `service/main.py`：HTTP API；`service/demo.py`：首期结算全流程演示。
